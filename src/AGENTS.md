# Защита рабочей цепочки публикации лидов в MAX

## Критический инвариант

Проверенная пользователем цепочка публикации лидов в MAX считается зафиксированной и не должна изменяться, упрощаться, переноситься или рефакториться без отдельного явного разрешения пользователя.

Обязательное поведение:

1. MAX-канал обнаруживается один раз через официальный `POST /subscriptions` и события webhook `bot_added` или `message_created`.
2. Точный числовой `chat_id` сохраняется глобально в `MaxBotChat` и после этого доступен для выбора во всех категориях. Повторное обнаружение для каждой категории не требуется.
3. При сохранении категории с включённой публикацией все существующие неудалённые лиды со статусом `NEW` ставятся в `BotDelivery` для выбранного канала.
4. Каждый новый лид создаётся вместе с заданиями доставки одной транзакцией через `createLeadWithDeliveries`.
5. Дедупликация `lead-channel:<leadId>:<chatId>`, очередь, блокировка задания, повтор временных ошибок и фоновый диспетчер должны сохраняться.
6. Недоступность MAX не должна блокировать парсер или приводить к потере лида.
7. Публичный тизер не должен раскрывать телефоны, email, ссылки или username; полный контакт доступен только после покупки.
8. Нельзя возвращать получение канала по публичной ссылке или через снятый с поддержки `GET /chats`.

## Защищённые участки

- `src/services/bot-outbox.ts`
- `src/lib/max-bot.ts`
- `src/app/api/webhooks/max/route.ts`
- `src/app/api/admin/bot/chats/route.ts`
- логика витрины в `src/app/api/admin/category/route.ts`
- точки вызова `createLeadWithDeliveries` в парсере и ingest API

Перед изменением этой цепочки необходимо сначала сообщить пользователю, какое именно проверенное поведение будет затронуто, и получить явное разрешение. Исправления вне этой цепочки не должны менять её побочно.

## Обязательная проверка

После разрешённого изменения необходимо выполнить:

```text
npm test
npm run typecheck
npm run build
```

Также обязательно проверить, что `scripts/parser_worker.py` не изменён.
